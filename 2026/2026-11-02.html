A. 今日最重要 Agent 论文 Top 5
1. Scaling Laws for Tool-Use Agents via Controllable Environment Synthesis（SynthAPI）
Andrew Szot、Samira Abnar、Alexander Toshev 等｜Apple（论文 HTML 标注）｜2026-10-27｜arxiv.org/abs/2610.37648

核心贡献：提出可控的工具环境合成流水线 SynthAPI，可以沿“工具、任务、数据库”三个维度分别控制多样性。在此基础上，首次给出预测工具使用 Agent 泛化能力的数据 scaling law。

关键技术：合成 458,752 个任务，在 4 种模型规模上训练 849 个模型，系统扫描数据规模与数据组成，拟合下游泛化与环境组成之间的关系。

重要实验结果：

  • 数据预算增大后，增加工具和数据库多样性比增加任务数量更有效；提高数据复杂度的收益更大（摘要）；
  • 按 scaling law 选出的数据配方迁移到 AppWorld、BFCL、ASTRA-Bench 等基准，在每个模型规模上都比最强的逐基准合成基线高：AppWorld Test-Challenge 高 7.6–11.6pp，BFCL 高 2.0–3.7pp（正文）；
  • 同等数据预算下，优于“只扩任务数”的配方，也优于用以往大规模工具数据训练的模型。

重要性：工具使用数据合成过去主要靠经验调参。这项工作用 849 个模型的大规模对照，把“该造什么样的环境”变成可以预测的问题。

未来影响：环境合成（Agent Gym、Env Scaling）团队会转向按多样性维度分配预算；“环境数 / 工具数”可能成为与 token 数并列的训练规模指标。

开源状态：摘要和正文中没有看到代码链接。

2. Agentic Backdoors via Pretraining Poisoning
Xinyan Hu、Pingbang Hu、Nicholas Carlini、Matthew Jagielski、Javier Rando、Yiming Zhang 等｜Anthropic、Anthropic Fellows Program、UC Berkeley、UIUC、UCL｜2026-10-27｜arxiv.org/abs/2610.37741｜代码：github.com/safety-research/agentic-backdoor

核心贡献：首次端到端证明：在预训练语料中投毒，可以让后来用干净流程后训练出的 CLI Agent 带上远程代码执行后门。触发条件出现时，Agent 会执行攻击者指定的命令；平时行为正常。

关键技术：从零预训练 0.6B、1.7B、4B 的 Qwen3 架构模型，再用干净的后训练流程把它们训练成 CLI Agent，并设计了新的投毒样本格式。

重要实验结果：

  • 投毒比例 0.1% 时，4B 模型攻击成功率约 92%；
  • 攻击成功率随模型规模增大而上升；
  • 投毒比例降到 0.0005% 时，攻击成功率仍大于 0（摘要）。

重要性：Agent 安全研究大多集中在提示注入和 skill 投毒。这项工作把威胁前移到预训练阶段，并且显示“干净的后训练”无法洗掉后门；规模越大风险越高，这一点尤其值得警惕。

未来影响：会推动预训练数据溯源、面向 Agent 动作的后门检测、命令执行沙箱默认开启等方向，也给前沿实验室的数据管线安全评估增加了必须考虑的一项。

开源状态：代码已开源。

3. Evolving Agent Teams（EAT）
Shiyi Cao、Ziming Mao、Dacheng Li、Joseph E. Gonzalez、Ion Stoica｜UC Berkeley（Sky Computing Lab）｜2026-10-27｜arxiv.org/abs/2610.36848｜代码：github.com/caoshiyi/EAT

核心贡献：作者发现，现有 Coding Agent 优化专家写的生产级 kernel（如 FlashInfer）时会陷入局部最优。EAT 用一个中心 supervisor 诊断局部最优的原因，然后重组整个 Agent 团队。

关键技术：supervisor 诊断后重组团队；持久文件系统作为团队记忆，包括学习文档、演化历史和每个团队的产物，用这些积累的经验指导重组。

重要实验结果：

  • 相同 token 预算下，稳定优于强 Coding Agent 基线；
  • 扩大预算后，从零生成的 MLA paged decode kernel 平均比 FlashInfer 生产实现快 1.2 倍，在 FlashInfer-Bench 的 47 个生产负载中赢 36 个（其余 11 个为 0.86–0.99 倍）；
  • KDA prefill 在 AMD MI350X 上比 vLLM 快 3.01 倍，在 NVIDIA B200 上比 FlashKDA 快 3.44 倍；
  • RoboDojo 机器人操作任务在保留种子上得 62.1，排行榜最佳为 55.3（摘要）。

重要性：这是开放式优化问题上，“多 Agent + 持久文件记忆 + 结构重组”超过单 Agent 演化（如 OpenEvolve 类方法）的有力证据。结果直接对标生产级 kernel。

未来影响：AI 写系统基础设施（kernel、serving）正从 benchmark 走向生产，可以和 C 部分的 InfraDev 对照阅读。

开源状态：代码已开源。

4. Spine: Compiling Subtask Trees into Structured Context for Long-Horizon Coding Agents
Jiahong Xiang、Kunqiu Chen、Lingming Zhang、Yuqun Zhang｜作者含 UIUC 的 Lingming Zhang 和南方科大的 Yuqun Zhang（机构根据作者推断，未逐一核对）｜2026-10-27｜arxiv.org/abs/2610.37224

核心贡献：Agent 用 work scope 显式声明子任务边界，同一个 Agent 内联执行嵌套子任务；只有独立的并行任务才交给子 Agent。这样把“子任务粒度”和“由谁执行”两件事拆开了。

关键技术：运行时维护一棵持久的 SpineTree。每次调用模型前，把这棵树即时编译成上下文：未完成子任务保留完整交互，已完成子任务只保留结果，并且保持前缀缓存可复用。

重要实验结果：

  • 接入 Codex（GPT-5.6 Sol）：SWE-Milestone 分数提高 11.8%，总成本降 32.4%；ProgramBench 平均测试通过率提高 17.3%；10 个 FrontierSWE 任务中 8 个的 Mean@5 提升；
  • 分数与 Recursive Subagent 相当，总成本低 73.7%；
  • 接入 Pi（Gemini 3.8 Flash、Qwen 3.8 27B）：SWE-Milestone 提高 9.5–17.5%（摘要）。

重要性：和上一份日报的 Hidden Costs of Forgetting、本期的 Physical Cost of Context 一致：上下文压缩必须和缓存前缀一起设计。Spine 给出了一个能直接落地的结构化方案。

未来影响：Coding Agent harness 可能从“线性历史 + 摘要压缩”转向“任务树 + 即时编译上下文”。

开源状态：摘要提到给 Pi 做了“可复用软件包”，但没有给出链接。

5. Sandman: Building and Operating Sandboxes for Agentic RL on Shared Kubernetes
Yiming Yan、Hongyang Wang 等 15 人｜Amazon（摘要自述）｜2026-10-29｜arxiv.org/abs/2610.39711

核心贡献：介绍 Amazon 生产环境中服务于 Agentic RL 工具执行和评测的沙箱系统，并分享运维经验。

关键技术：每个沙箱是一个 Kubernetes pod，往未修改的任务镜像里挂载一个小 daemon；文件和进程在多次调用间保持，直到训练框架释放；系统负责创建、就绪检测和回收。

重要实验结果：

  • 规模测试中同时承载 11,858 个小型沙箱；
  • 2026 年 10 月，4 个生产 SWE-bench Verified 训练任务共创建 310 万个沙箱；
  • 总结了突发创建、环境预热、回收被遗弃的沙箱、受控评测等工程取舍（摘要）。

重要性：Agentic RL 的瓶颈正在从 GPU 转向环境。这是少见的大厂生产级 rollout 沙箱运维报告，和 E2B、Daytona、kubernetes-sigs/agent-sandbox 等开源方案直接相关。

未来影响：给自建 SWE RL 训练平台的团队提供了容量规划和故障模式的参考，可以和 C 部分的 EnvSched（rollout 调度）配合使用。

开源状态：作者承诺开源 daemon、provider 和 pool，目前还没有发布。

B. Agent Memory 专题
今日主推：Long-Term Agent Memory through Complementary Curation and Consolidation
Abhishek Gupta、Dongge Han、Victor Rühle、Saravan Rajmohan 等｜Microsoft｜2026-10-29｜arxiv.org/abs/2610.39790

方法：用两个互补的扁平存储代替单一记忆：情景记忆（episodic）保留叙事上下文和时间顺序，结构化关系记忆（类似 semantic memory）保存紧凑、可查询的关系条目。再加一个离线 consolidation 机制，合并相关或冗余的条目，删除冲突或过时的条目。

相对已有工作的改进：不像 Zep 那样构建时序知识图谱（需要做实体消解、边去重），也不像 A-Mem 那样维护 Zettelkasten 式动态链接，所以工程复杂度更低；实验表明两类记忆稳定互补。

实验结论：

  • 摘要报告：LoCoMo 准确率 90.2%，LongMemEval-S 准确率 85.5%（最优 backbone，LLM-judge 口径）；
  • 正文表格（gpt-4o-mini，LoCoMo，整体 LLM Score）：本方法 0.835，FullContext 0.790，Nemori 0.744，Mem0 0.613，LangMem 0.513；
  • LongMemEval-S 上，multi-session 0.801 vs Nemori 0.556，knowledge-update 0.902 vs 0.795，上下文只需约 3–6.9K tokens（full-context 为 101K）；
  • 值得注意：加入 consolidation 后，gpt-4o-mini 的 LLM Score 从 0.835 小幅降到 0.823，它的主要价值在效率和存储规模，而不是准确率。

复现资源：没有看到代码链接；基准 LoCoMo 和 LongMemEval-S 是公开的。

其他值得看的记忆工作
过时事实比无关证据更有害：When Retrieval Is Not Enough
arxiv.org/abs/2610.36308｜10-26

  • 基于 MemoryAgentBench 的 FactConsolidation 任务；Qwen2.5-7B、6K 历史、BM25 检索：证据预算从 64 token 加到 512 token，准确率从 45% 降到 32%，尽管每个检索集合里都包含最新事实；
  • 在证据大小相同的条件下，把一条无关陈述换成过时的竞争陈述，准确率从 100% 降到 44.6%（Qwen3-14B 为 87.8%）；
  • 结论：记忆的 update 和失效处理，比 retrieval recall 更关键。

生命周期治理：CALM
arxiv.org/abs/2610.38573｜10-28

把“持久保存”和“查询时准入”分开处理。记忆单元带有效性和生命周期状态，用支持、冲突、依赖三类信号更新；查询时按时间适用性做门控准入。在 LongMemEval-S 和 LoCoMo 上（Qwen 与 GPT backbone）整体准确率最好，同时保留过时记忆，用来回答“过去的状态是什么”这类问题。正好回应了上一篇指出的问题。

Coding Agent 的仓库记忆：Stratum
arxiv.org/abs/2610.36153｜10-26

实测发现：KV cache 形式存储知识所需的字节数是索引文本的 10⁴–10⁵ 倍；在 752 个真实 bug 修复中，47% 的共改文件对没有结构上的连接，只能从历史中挖掘。分层仓库记忆配合 page-safe 工具（每次返回都说明给了什么、还剩什么、花了多少）：新会话继承上一会话（由另一个模型写的）记忆后，24 次试验中有 21 次定位到根因文件，只检索的基线为 6/24，中位 token 成本低 4.5 倍。属于小样本研究（8 个 bug）。

Plan/Workflow 缓存的“编译”路线：FlashScript
Sumit Gulwani 等（作者含 Microsoft 研究者，机构未逐一核对）｜arxiv.org/abs/2610.33876｜10-24

把一次成功的 Agent 运行编译成可复用的神经-符号程序：动作和数据变换写成代码，实例相关的值变成参数，只在需要判断的地方调用 LLM。WorkBench 120 个分析任务上（Claude Haiku 4.5），每次运行都正确且工具调用完全一致，输入 token 约少 70 倍，运行时间约为 skill 引导 Agent 的三分之一；在任务的组合版本上，skill 引导 Agent 的准确率降到 23%。同期的 SkillCompiler（arxiv.org/abs/2610.39508）也把 skill 中定义清楚的操作编译成程序。

记忆优化的监督信号：MemSteer
Jie Huang、Cuiling Lan、Yan Lu 等｜arxiv.org/abs/2610.39276｜10-29

把没有标注的用户历史自动变成带证据的 QA 监督，用来在不更新参数的情况下优化记忆的存储、检索和上下文构造。在 ATM-Bench 和 RHELM 上，这种监督的效果与官方 QA 相当。可以把记忆系统当作“可调参的系统”，在新用户上做自动调优。

安全与隐私
arxiv.org/abs/2610.38209（RGA，10-28）｜arxiv.org/abs/2610.38521（CLAUDE.md 类记忆文件，10-28）

  • Role Grounding Attack：在社交交互中嵌套“攻击者用户的偏好”，让受害 Agent 把这个偏好记成自己用户的偏好，进而操纵工具选择、泄露隐私。在 5 个主流记忆系统和 6 个模型上攻击成功率都很高；
  • 恶意 CLAUDE.md 等记忆文件：在 12 类 CWE、36 个 SecRepoBench 任务上，安全完成率变化在 −8 到 +6pp 之间，没有一致规律；但不同 Agent 是否告诉开发者“这个文件影响了生成的代码”差异很大。

Cache 视角：The Physical Cost of Context
Jishen Zhao 组（UCSD，按作者推断）｜arxiv.org/abs/2610.34763｜10-26

在 SWE-rebench V2 的 450 个定位任务上：开启前缀缓存后，Eager 预加载策略的 prompt 量基本不变（+8.3%，95% CI 跨 0），但未缓存的 prefill 减少 67.7%；删除历史可能把 token 节省变成额外计算。和上一份日报的 Hidden Costs of Forgetting 是独立重复验证，结论一致。

与主要技术路线的关系
  • MemGPT/Letta：Microsoft 的混合记忆和 CALM 都在“分页”之外补上了离线 consolidation 和查询时准入，相当于给 Letta 式的 archival memory 增加生命周期管理；Stratum 的 page-safe 工具延续了 MemGPT 的分页思路，并给每次返回加上成本说明。
  • G-Memory 等图或层级记忆：Microsoft 方案刻意不用图（与 Zep 对比），用两个扁平存储也取得了 SOTA，说明“结构复杂度”不等于效果；HEDGE（arxiv.org/abs/2610.38902）则用超图做多 Agent 辩论记忆，是图路线的延伸。
  • Agentic Plan Caching：FlashScript 和 SkillCompiler 把“缓存计划”进一步推到“编译成程序”，复用粒度从 plan 模板变成可测试的代码资产。
  • RAG/Cache：“过时事实”研究表明扩大检索预算可能降低准确率；Spine 和 Physical Cost of Context 表明，上下文工程必须对前缀缓存友好。
C. 其他值得关注的新论文
Coding Agent
InfraDev：Coding Agent 能开发 AI 基础设施吗？
Luo Mai 组｜爱丁堡大学、腾讯混元｜arxiv.org/abs/2610.36589｜10-27

基于 Megatron-LM、vLLM、verl 的真实 PR 构建 36 个多 GPU 任务。6 个前沿模型中最好的只解决 38.9%；隐藏探针拒绝了 32% 通过全部官方测试的提交；如果用原始 PR 描述作为 prompt，没有任何模型能解决任何一个任务。

CodeSpecWeave：相互依赖规格下的长程编码
Yishuo Cai、Xu Sun、Fuli Luo 等｜arxiv.org/abs/2610.40256｜10-29

合成 4,670 个训练任务（覆盖 2,865 个仓库），任务带有相互耦合的规格；在这些任务上做 RL 后，DeepSWE-v1.1 上明显超过基线。同时发布 CodeSpecWeave-Bench（100 个任务、1,044 条规格）。

Computer Use
VeriCUA：把验证当作 Agent 探索
Google、香港大学（Lingpeng Kong、Ravi Kumar 等）｜arxiv.org/abs/2610.40578｜10-29

跨平台的 CUA 任务完成验证器：先构建 rubric，再按需选择 GUI 检查或代码检查来收集证据。离线难例上提升最大，在线能更好地拒绝虚假的完成声明。可以直接用于 CUA 的数据筛选和 RL 奖励。

D. 今日趋势判断
  1. Agent 训练数据开始“规律化”：SynthAPI（849 个模型的 scaling law）、CodeSpecWeave（规格耦合的任务合成）、EnvSched（环境级调度），加上上一份日报的 WorkFactory，说明环境和任务合成正在从手工经验变成可度量、可预测的工程。
  2. 攻击面下沉到训练数据和持久状态：预训练投毒（Anthropic）、RGA 记忆角色混淆、恶意 CLAUDE.md，加上上期的 Poisoned Skills 和 Evolve-IPI，攻击对象从单轮 prompt 扩展到“Agent 会长期信任的东西”。
  3. 上下文工程与 KV/前缀缓存深度耦合：Spine、Physical Cost of Context、TAO 的缓存收益打分、Stratum 的 KV 与文本存储成本对比，加上上期 Hidden Costs of Forgetting，至少 5 项独立工作得出同一结论：只算 token 数会误判真实成本。
  4. 记忆研究的重心从“检索到”转向“判断对错和时效”：Obsolete Facts、CALM、Microsoft 的 consolidation、HABIT-Bench（arxiv.org/abs/2610.24520，10-17 首发，热度 39）都在处理冲突、过时和习惯变化。
E. 研究机会
1. 带时效感知的记忆准入基准与基线（Agent Memory）

  • 在 MemoryAgentBench FactConsolidation、LongMemEval knowledge-update 子集上，系统控制“过时竞争陈述”的比例和位置，复现 arxiv.org/abs/2610.36308 中检索预算越大准确率越低的现象；
  • 对比 CALM 的门控准入、Microsoft 的离线 consolidation，以及零 LLM 的“版本号 + 时间戳去重”简单基线，画出“准确率 vs 记忆写入成本”曲线；
  • 可以写成一篇短论文，或者做成 Mem0 / Letta 插件。

2. 前缀缓存友好的子任务上下文编译器（Agent Infra / Coding Agent）

  • 把 Spine 的“任务树即时编译”思路做成 OpenHands 或 mini-SWE-agent 插件，在 SWE-bench Verified 上同时统计 cache-hit token、未缓存 prefill 和成功率；
  • 按 Physical Cost of Context 的协议测能耗；研究问题：已完成子任务的结果摘要放在缓存断点之后，是否能同时拿到 Spine 的准确率提升和接近 100% 的前缀复用？

3. Agent 后门的数据侧检测（Agent 安全 / Infra）

  • 基于开源的 safety-research/agentic-backdoor，在 0.6B 到 1.7B 规模上，评估“动作级异常检测”（命令执行前在沙箱中做行为差分）和“预训练数据溯源过滤”的检出率；
  • 结合 Sandman 式沙箱，研究运行时防御能否在不改模型的前提下把 92% 的攻击成功率压到 5% 以下。
